# Design Context — 教师端（重点：备课对话界面）

> 由用户于 2026-09-14 明确确认。**这是设计决策的唯一依据**，不得从代码反推。
> 与 `.impeccable/design.json`（语义 token 治理 sidecar，被 `test/visual/semantic-token-governance.test.ts` 消费）**互不干扰**。

## Target audience

**一线高中数学教师。**

- 熟悉教材与教学法，但**时间极度紧张**（备课常在晚上 / 课间碎片时间）
- 不是技术用户：不懂 `locator`、`no_units`、`rule_extraction_fallback` 这类内部词
- 对"AI 胡说"高度敏感 —— 数学是硬学科，错一个符号就不可用
- 对"等"的容忍度低，但**能接受有明确进度提示的等待**

## Use cases（按优先级）

1. **快速出片**（第一优先）
   - 一句话 → 可上课的课件
   - 要求：路径短、信息密度高、AI 慢但必须给出**可信的进度与阶段**
   - 反面：22 个教材选项平铺、无分组无搜索、必须逐级点选

2. **多轮精修**（第二优先）
   - 反复打磨教案 / 课件细节
   - 要求：版本清晰、改动可 diff、可回退、**改动理由可见**
   - 反面：只给"AI 修改提案 基于修订 3"这种编号，看不出改了什么

明确**不作为**核心场景：团队接力、复用旧课改造（可存在，但不为它们牺牲前两项的简洁度）

## Brand personality

**温和陪伴。**

像一位有经验、有耐心的带教师傅，不是冷冰冰的效率工具。

具体落到界面：

| 维度 | 取向 |
|---|---|
| 文案语气 | 第二人称、口语化、给台阶（"我们一轮一轮聊清楚" 而非 "请提交参数"） |
| 出错时 | **不甩术语、不指责**；说清发生了什么 + 下一步能做什么 |
| 留白 | 中偏松：宁可少放一个控件，也不要让教师做无谓的选择 |
| 信息密度 | 对话流内**克制**（一屏说清一件事）；产物/编辑器内可以高密度 |
| 动效 | 柔和、短促、有方向感；不做炫技 |
| 术语 | **中文优先**。内部标识符一律不得出现在用户可见文本里 |
| 颜色 | 沿用 `--ma-*` 语义 token；主蓝 `#2563EB`；温和不等于花哨 |

## 已知必须遵守的既有铁律（不可推翻）

- T22.1 DESIGN-CORRECTION-R1：**禁 Stepper / Wizard / 固定三栏**；进入 TeachingSession 收起全局侧栏（Focus Mode）；
  链路只通过**对话消息里的 typed artifact** + 顶部轻量"备课进展"Drawer + 按需 Artifact Focus 表达
- 组件内**禁 raw hex / rgb / shadow**，一律 `var(--ma-*)`；唯一允许字面色值处是 `src/platform/design-system/tokens.ts`
- 图标复用现有图标库，**不用 emoji 代替正式图标**
- 冻结域（不可碰）：`src/pages/teacher-v3/SlidesView.vue`、`src/components/teacherV3/SlideCanvasV3.vue`、
  `src/types/teacherV3.ts` 的 V3 部分、`src/api/teacherV3.ts` 现有 PPT/Plan 方法、旧模板颜色卡 / 旧 wizard / 旧导出交互

## AI Slop Test（自检清单）

改完任何界面，逐条自问：

- [ ] 有没有把内部标识符（`textbook` / `no_units` / `rule_extraction_fallback` / `locator`）露给教师？
- [ ] 有没有中英混杂？
- [ ] 有没有让教师在无意义选项里做选择（如平铺 22 个教材）？
- [ ] 出错时是不是只说"刷新查看新版本 / 重试"，而没告诉他**发生了什么**？
- [ ] 是不是用了 emoji 冒充图标？
- [ ] 是不是出现了通用紫色渐变 / 玻璃拟态 / 暗色霓虹？
- [ ] 组件里有没有硬编码色值绕开 `--ma-*`？
- [ ] 有没有把"等待"做成无反馈的白屏或转圈，而没有阶段提示？

## 待办（按此上下文排优先级）

1. 教材选择卡：22 项平铺 → 需分组（学段 / 版本）+ 搜索
2. 错误卡语气：「刷新查看新版本 / 重试」→ 需说明发生了什么 + 下一步
3. `no_units` / `rule_extraction_fallback` 等 `warnings` 内部码 → 需中文人话映射
4. 「AI 暂时不可用，你可以手工填写」出现在对话流中 → 需改为温和引导
5. 长耗时（实测 intent 平均 22.7s、最长 246s；blueprint 平均 23.5s、最长 560s）→ 需可信的阶段进度
