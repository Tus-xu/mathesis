# DEF-001 · EventPublisher.publish_durable 首事件即崩（Result 二次消费）

| 项 | 内容 |
|---|---|
| 编号 | DEF-001 |
| 严重级 | **P1**（事件双通道是 B3 灵魂基建，M1 Gate 前置；G4/SSE 恢复协议全被阻塞） |
| 所有者 | **B3**（app/core/events.py 属 B3 所有权，B5 只记录不代修） |
| 状态 | OPEN（2026-09-07 登记） |
| 复现 | 确定性：任何 `publish_durable` 首次调用 |
| 环境 | teacher-platform 骨架 @ feat/backend-m1（未提交态）；aiosqlite 最小复现实证 |

## 现象

`app/core/events.py` `_alloc_seq()`（约 :107-118）对**同一个** SQLAlchemy `Result`
对象连续调用两次 `scalar_one_or_none()`：

```python
row = await session.execute(
    select(table).where(...).order_by(getattr(table, "seq").desc()).limit(1)
)
seq = (row.scalar_one_or_none().seq if row.scalar_one_or_none() else 0) + 1
#      ^ 第二次调用时 Result 已消费 → ResourceClosedError
```

条件表达式 `X if row.scalar_one_or_none() else 0` 先后求值两次 `scalar_one_or_none()`，
第二次触发 `sqlalchemy.exc.ResourceClosedError: This result object is closed.`

## 实证（aiosqlite 最小复现，2026-09-07 B5 阶段0）

```
DOUBLE-CALL BUG: ResourceClosedError This result object is closed.
```

复现脚本语义与 `_alloc_seq` 逐行同构（select … order by seq desc limit 1 后条件表达式二次消费）。

## 影响

- 首条 durable 事件发布即抛异常 → deck/plan/photo-ingest/grading/**classroom 事件**全部无法落库；
- `UNIQUE(scope, seq)` 双写协议、snapshot+after(seq) 恢复（红线 7）在其上游，整体不可用；
- M1 ValkeyCompatibilityGate 与 M2-A 串行 Gate 直接被阻。

## 建议修法（B3 自证，B5 复验）

```python
current = (await session.execute(...)).scalar_one_or_none()
seq = (current.seq if current is not None else 0) + 1
```
