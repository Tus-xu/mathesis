# DEF-004 · run_task 成功路径漏调 _finish：任务完成后永远停留 running

| 项 | 内容 |
|---|---|
| 编号 | DEF-004 |
| 严重级 | **P1**（任务生命周期成功态永不闭合——任务中心「进行中」恒挂、导出/生成任务无法回执 done） |
| 所有者 | **B3**（app/tasks/registry.py 属 B3） |
| 状态 | OPEN（2026-09-07 由 B5 ValkeyCompatibilityGate 全链用例实证） |
| 复现 | 入队 `demo_sleep` 任务 → 真实 worker 执行完成（task_events 有 status+progress×4 全量事件，progress=100）→ `tasks.status` 仍为 `'running'`，无 seq=6 的 `done` 事件 |

## 现象

`app/tasks/registry.py` `run_task`：

```python
try:
    await handler(task_id, publisher=publisher, user_id=user_id)
except Exception as exc:
    logger.exception(...)
    await _finish(publisher, tid, "failed", error=str(exc))
# ← 成功路径没有 else / 尾部 _finish(done)
```

handler 成功返回后**没有任何代码**调用 `_finish(publisher, tid, "done")`——只有失败分支写了终态。

## 实证（B5 Gate，真实 worker + 真实 Valkey/PG）

- 入队 3 个 `demo_sleep`：全部执行到 progress=100 事件，`tasks.status='running'` 恒挂；
- 同期 5 个失败任务（unknown type 路径）反而正确落到 `failed`——证明 `_finish` 本身可用，仅成功路径缺失；
- 影响：`GET /tasks` 的 running 计数虚高（L1 判定②）；导出/生成等异步任务教师永远看不到完成回执（#70 行为契约）。

## 建议修法（B3 自证，B5 复验）

```python
try:
    await handler(...)
except Exception as exc:
    ...
    await _finish(publisher, tid, "failed", error=str(exc))
else:
    await _finish(publisher, tid, "done")
```
