# DEF-003 · 幂等中间件前缀错位：所有教师端写请求被静默跳过（Idempotency-Key 失效）

| 项 | 内容 |
|---|---|
| 编号 | DEF-003 |
| 严重级 | **P1**（G8 幂等契约对教师端全量失效——重复提交会真实双写，仅 DB 层唯一约束兜底的端点幸免） |
| 所有者 | **B3**（app/core/idempotency.py 属 B3） |
| 状态 | OPEN（2026-09-07 登记，代码走查发现；compose 档 `test_idempotency.py` 复现） |
| 复现 | `POST /api/teacher-v3/quiz/questions` 带 `Idempotency-Key: k1` 两次 → 各建一行（预期：重放首结果、仅一行） |

## 现象

`app/core/idempotency.py:29-30`：

```python
_IDEM_SKIP_PREFIXES = ("/teacher-v3",)
...
if not any(request.url.path.startswith(p) for p in _IDEM_SKIP_PREFIXES):
    return True   # 跳过
```

真实线缆路径是 **`/api/teacher-v3/...`**（前端 `BASE='/api'` + vite 代理不剥前缀，
`D:\frontend\vite.config.js:38`；B3 自己的路由挂载也是 `prefix="/api/teacher-v3"`，
`app/api/routes.py`）。因此 `startswith("/teacher-v3")` 恒 False → `_should_skip` 恒 True →
**中间件对全部教师端请求直接放行，Idempotency-Key 语义完全未启用**。

## 影响

- G8「REST 写端点 Idempotency-Key → 15min 窗口重放首结果」契约面 100% 失效；
- L6 判定①（聚类反馈确认幂等，Idempotency-Key 生效日志）无法取证；
- 03-ACCEPTANCE §14 覆盖清单（submit answer / confirm card / push / upload / export / join）全暴露在双写风险下。

## 建议修法（B3 自证，B5 复验）

`_IDEM_SKIP_PREFIXES = ("/api/teacher-v3",)`（或统一用 app 挂载前缀常量），
并在 `tests/unit/platform/` 补一条「带 /api 前缀的路径不被 skip」单测。

## 出口条件（B5 回归）

1. compose 档 `tests/contract/test_idempotency.py::test_rest_idempotency_replays_first_response` 转绿；
2. 并发同 key 用例（`test_concurrent_same_key_no_double_write`）只产生一行。
